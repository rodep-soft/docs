# CIの利用方法

## CIをなぜ導入するのか

CIを導入するメリットは多岐にわたりますが、特に重要な理由は以下の3点です。

- **環境差異による不具合の撲滅（It works on my machine の解消）**
  毎回クリーンな環境でビルドを行うため、個人のローカル環境依存による見落としを防ぎ、誰の環境でも動くことを保証できます。
- **開発者のリソース・時間の解放**
  重いビルドやテスト処理をクラウド側に委ねられるため、手元のPCが重くならず、処理完了を待たずに次のタスクへ着手できます。
- **コードレビューの効率化**
  ビルド可否や単純な実行エラーの検知はCIが自動で行うため、レビュアーは設計やロジックの確認といった人間にしかできない本質的な議論に集中できます。

プロジェクトの規模が拡大するほど、CIの導入によって得られる費用対効果（リターン）は大きくなります。

## CIを導入する

1. .github/workflowsのディレクトリを作る(プロジェクトルート直下)
   GitHub Actions のワークフローを格納するディレクトリを作成します。

```bash
mkdir -p .github/workflows
```

2. ci.yamlを作る
   作成したディレクトリへ移動してファイルを作成し、元のルートへ戻ります。

```bash
cd .github/workflows
touch ci.yaml
cd ../..
```

3. task-runnerを記述する

   [CIの書き方](../../base_knowledge/etc/ci_write.md)

### extra：手元のPCでCIを回す（Self-hosted runnerを使う）理由

ここまでCIのメリットを説明してきましたが、場合によってはGitHubのクラウド環境ではなく、あえて自分のPC（Self-hosted runner）でCIを回すように構成することがあります。主な理由は以下の2点です。

- **マシンスペックの強化によるビルド高速化**
  GitHubが標準で提供する仮想環境は2コア / 7GB RAM程度とスペックが控えめです。C++やRustのフルビルド、機械学習のテストなど負荷の高い処理ではビルドチェックに膨大な時間がかかってしまいます。手元のハイスペックなマルチコアCPUや潤沢なメモリ、GPUリソースを活用することで、実行時間を大幅に短縮できます。

- **実行時間（月間枠）の制限解除**
  プライベートリポジトリではGitHub提供のランナーに月ごとの実行時間制限（無料プランなら月2,000分など）が設けられています。自前のPCをランナーとして登録すれば、実行枠を消費せず完全無料で無制限にCIを回し続けることができます。
